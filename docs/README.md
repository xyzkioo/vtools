# vtools 模块介绍

本目录汇总各功能模块的用途、实际入口、输入输出和使用边界。介绍按用户可运行的功能组织，内部 adapter、core 和运行时在所属模块中说明；完整参数以各入口 `--help` 和链接的配置、原模块文档为准。

## 模块导航

| 模块 | 用途 |
| --- | --- |
| [统一命令行与配置](modules/entrypoints.md) | 把检测诊断、可视化、测速、一致性检查和压缩分发到已有后端，适合脚本调用和重复实验。 |
| [数据集质量检查](modules/dataset-quality.md) | 训练前只读扫描本地 YOLO 检测数据集，检查图片、标签和划分问题，无需加载模型。 |
| [检测诊断](modules/diagnostics.md) | 基于真实标注和预测结果定位错误原因，保留逐图、逐目标和差图证据。 |
| [模型可视化](modules/visualization.md) | 观察指定层特征、指定目标 CAM，以及检测头候选到最终框的筛选过程。 |
| [性能测速与一致性](modules/speed-test.md) | 比较固定输入下的 PyTorch 模型调用和 TensorRT engine 调用，检查权重恢复、显存和跨后端输出。 |
| [模型压缩](modules/compression.md) | 生成量化、剪枝或蒸馏后的模型，记录基线和处理后的评估结果。 |
| [数据与 K230 转换](modules/conversion.md) | 将 NDJSON 数据集转为本地 YOLO 格式，并连接 PyTorch/Ultralytics、ONNX 与 K230 .kmodel 转换校验。 |
| [图片、视频与文件名工具](modules/file-tools.md) | 提供不加载模型的数据准备功能：批量缩放、视频抽帧及图片与标注同步改名。 |
| [环境检验](modules/environment.md) | 核对实际 Python、依赖、CUDA 和 Ultralytics 源码来源，帮助定位导入路径与模型构建问题。 |
| [桌面工作台](modules/workbench.md) | 用 React 与 pywebview 统一配置编辑、任务启动、日志、历史和结果预览，任务仍调用各模块原有后端。 |
| [桌面打包与公共运行时](modules/packaging.md) | 把工作台和工具资源打成桌面目录包，再生成 Ubuntu/Debian 安装包；公共运行时帮助各模块发现独立 Ultralytics Fork。 |

## 建议使用顺序

1. 用环境检验确认目标 Python 和模型依赖；训练前先做数据集质量检查。
2. 用检测诊断定位错误，再按需要使用特征、CAM 和阶段追踪查看模型内部。
3. 用测速与一致性检查评估后端；压缩后重新验证精度和目标设备性能。
4. 部署 K230 时执行转换与主机校验，再进行板端验收。

桌面工作台和命令行使用同一套工具后端，可按习惯选择。模型实验通常写入独立 `runN`；图片、视频、改名及转换工具的输出规则见各自介绍，不能假设所有工具都生成相同报告。
