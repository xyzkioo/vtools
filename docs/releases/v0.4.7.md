# v0.4.7：压缩处理模式与学生类别适配

更新日期：2026-10-16。

## 使用变化

模型压缩页面按模型任务选择一种处理模式，相应评估与保存步骤自动执行：

| 模型任务 | 可选模式 |
| --- | --- |
| detect | 基线评估、结构化剪枝、非结构化剪枝、检测知识蒸馏 |
| classify | 基线评估、非结构化剪枝、分类知识蒸馏、动态 INT8 量化 |

检测知识蒸馏只需教师权重、学生初始化权重和检测数据集 YAML，不需要公共模型权重。剪枝、量化和基线模式使用公共模型权重。界面仅提交当前模式使用的输入，切换模式后隐藏字段中的旧值不会混入命令。

处理模式转换成已有的 `--only` 模块列表，覆盖 YAML 中其他模块开关。CLI/YAML 仍可显式组合多个模块；命令行 `--only ''` 表示全部关闭。配置同时开启多种处理方式时，界面要求明确选择本次模式。

## 检测蒸馏

教师的类别数量、名称和顺序必须与数据集 `names` 一致，不匹配时在训练前拒绝。学生可直接使用通用 80 类预训练权重：按模型 YAML 重建目标类别检测头，迁移形状兼容的权重，分类输出按名称匹配迁移，新类别保留初始化。同类别数量但顺序不同也会重映射；无法按 YAML 忠实重建的已剪枝主干拒绝适配。教师与学生的蒸馏特征层索引及空间尺寸仍须兼容。

适配后的初始化另存为 `artifacts/distillation/student-initialized.pt`。学生基线、训练和产物父来源使用这份检查点，输入权重不覆盖。训练完成后重载 `student-best.pt`，检查独立学生结构并执行评估；前后指标及适配信息记录在 `summary.json.distillation`。

只运行检测蒸馏及其报告/导出配套模块时，多余的公共参数统计和公共基线标为 `skipped`，学生自身的参数统计和基线照常执行。包含剪枝/量化的组合继续使用公共基线。

结构化微调和检测蒸馏共用用户级 AMP 检查权重缓存 `~/.cache/ultralytics/weights/`；设置 `XDG_CACHE_HOME` 时改用其下的 `ultralytics/weights/`。训练数据镜像和模型产物仍保存在各次运行目录。

检测蒸馏需要支持 `distill_model/dis` 和 `DistillationModel` 的外部 Ultralytics Fork。可在 YAML 的 `project.ultralytics_repo` 或环境变量 `VTOOLS_ULTRALYTICS_REPO` 指定 Fork，普通 Ultralytics 安装缺少接口时会明确失败。模型运行库、权重和数据集不包含在 deb 中。
