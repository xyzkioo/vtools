## 行为变化

- 更新器不再限定 Linux：同时解析 GitHub Releases 里的 Windows 安装包与 Linux `.deb`，两个平台各自比较版本。
- “设置 → 软件更新”改为两行：`Windows x64` 与 `Linux (.deb)`，各自显示最新可用版本与状态（已是最新 / 可更新 / 尚无安装包 / 校验信息缺失）；非本机平台只显示版本，不提供安装按钮。
- Windows 走半自动安装：下载安装包 → 校验 SHA-256 与大小 → 调起 Inno Setup 安装向导，用户在向导里确认；不再需要 pkexec 或 apt。安装向导仍执行 `--install-check`。
- Linux 安装路径保留 pkexec + apt-get，但版本比较改为纯 Python 数字段比较，不再调用 `dpkg --compare-versions`；架构仍优先取 `dpkg --print-architecture`，缺失时回退到 `platform.machine()` 映射。
- 资产选择要求完全匹配平台命名：Windows 用连字符 `vtools-<版本>-windows-x64-setup.exe`，deb 用下划线 `vtools_<版本>_<架构>.deb`；缺少可信 SHA-256 摘要或大小的资产不会被提供安装。
- 跳过草稿版与预发布版；某个 release 只带一个平台的资产时，另一个平台沿用自己最新的那条版本，不再因为最新 release 缺资产而整体报错。

## 验证边界

- “检查更新”只读取发布信息与资产元数据，不下载安装包；Windows 的“下载并安装”会真实下载并校验，然后调起安装向导，最终安装仍由用户在向导里确认。
- 本次未在真实 GitHub 上执行 Windows 自更新到新版本的全流程（需要发布 0.5.8 之后再装 0.5.8 才能验证），只用单元测试覆盖版本比较、资产选择、摘要缺失与 Windows 调起向导的分支。
- 未在 Ubuntu 上实测 0.5.8 的 `.deb` 安装路径。
