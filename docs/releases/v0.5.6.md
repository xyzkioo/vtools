# v0.5.6 Windows 外部 Python 隔离修复

## 产物

- Windows x64：`vtools-0.5.6-windows-x64-setup.exe`
- 大小：160040220 字节（152.6 MiB）
- SHA-256：`adf3f466776e23d828d4f855e2f16cd0c1bf7e10fe78f08683e388a22926caec`

## 问题与修改

旧包将包含 Python 3.12 扩展的 `_internal/` 加入外部 Python 的 PYTHONPATH，导致 Python 3.10 的标准库误载 `_socket.pyd` 等 3.12 模块。Windows 的冻结 DLL 搜索目录也会被子进程继承。

工具脚本、配置和公共发现模块现位于独立的 `_internal/tool-sources/`，仅该纯源码目录加入模块路径。外部进程环境移除冻结 Python/Qt 路径及运行时变量；创建子进程期间清除 PyInstaller DLL 搜索目录，并在成功或异常时恢复原设置。Windows Conda 前缀和 Library/bin 按实际解释器布局确定。内置 worker 保留自身运行库配置。

## 实测

- 成功复现旧包：外部 Python 3.10 加入旧 `_internal` 后，import socket 报 python312.dll 版本冲突。
- 从完整新目录包分别启动 Conda Python 3.10 和标准 Python 3.12：socket、ssl、ctypes 和 importlib.metadata 可导入，各 `.pyd` 均来自所选环境；vtools_runtime 来自隔离源码目录。
- 两个外部解释器均可运行随包环境检查脚本的 --help；启动子进程后 Qt 运行库仍可用。
- 通过真实 TaskManager 调用外部 Python 3.10 环境检查：不再出现 ABI 冲突，准确报告所选 vtools-build 缺少 torch、torchvision、ultralytics（任务状态为失败，未伪报模型环境可用）。
- 桌面实际页面安装验收退出 0，内置文件改名预览和 UTF-8 日志通过。
- 环境清理与 DLL 异常恢复回归 2 项通过；工作台回归 53 项中 47 通过、6 跳过；Windows 内置 worker 分发回归通过。
- 前端、PyInstaller 目录包及 Inno Setup 安装包构建通过，语法编译与 git diff --check 通过。
