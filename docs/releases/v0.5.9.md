# v0.5.9 更新器限流规避

## 产物

- Windows x64：`vtools-0.5.9-windows-x64-setup.exe`
- 大小：158220960 字节（150.9 MiB）
- SHA-256：`dcc5a8e7cfd5ffdf69c24e79b1bfb406a37a0169127c8ed7bfaadc65ea27ee6e`
- 安装向导为英文；工作台界面为中文。前端、PyInstaller 目录包和 Inno Setup 安装包均已重新构建。

## 问题

0.5.8 的更新器只走 GitHub REST API（`/releases`）。未认证访问每小时只有 60 次/IP，且与浏览器、其他工具共享；额度用完后 GitHub 返回 403，工作台直接显示「更新失败，请稍后重试。Error: 检查更新失败：GitHub 返回 HTTP 403」，两条版本行也一起消失。本次发布前实测确认了该状态：`remaining: 0`，提示 `API rate limit exceeded`。

## 行为变化

- **发现版本改为两条路**：
  1. 官方 REST API 优先——它能给出 GitHub 服务端计算的 SHA-256 摘要（信任链最强）；
  2. 接口限流或不可达时，回退到 `releases.atom`（不走 REST，不受 60 次/小时配额限制）取版本号，再对每个候选版本的资产做 HEAD 取大小，并读取同目录的 `<资产>.sha256` 校验文件作为摘要。
- **再兜一层本地缓存**：两条路都失败时，使用 24 小时内的最近一次成功结果，并在界面提示“显示 x 小时前缓存的结果”，不再直接报错、也不再让两行数据消失。
- **命中即停**：回退路径只探测到每个平台第一个可用的版本就停止；回退耗时从 30 秒降到约 7 秒。
- **错误文案**：403/429 显示为「GitHub 接口访问次数受限」，并说明已切换到发布列表与 `.sha256` 校验文件。
- 界面新增一行来源提示：使用旁证或缓存时明确告知，API 正常时不显示。

## 验证边界

- 旁证路径的摘要来自发布时上传的 `<资产>.sha256` 文件，不是 GitHub 服务端计算值；它和安装包同在 HTTPS 的同一 release 下，能防止传输损坏与错误文件，但对“发布账号本身被篡改”的防护弱于 API 的 `digest`。因此 API 可用时始终优先用 API 摘要。
- 缓存只在网络完全不可用时兜底，最长 24 小时，过期即丢弃。
- 本次未在真实限流环境之外的异常网络（如 DNS 污染、代理中断）中验证。

## 实测

- 更新器单元测试 17 项通过：版本段比较、双平台独立解析、deb 命名、缺资产、摘要缺失、跳过草稿/预发布、限流回退到旁证、两条路都失败时用缓存、过期缓存丢弃、旁证缺失返回空、下载校验失败清理临时文件、Windows 调起向导不调用 apt。
- 在本机真实限流状态下（API 剩余 0）实测回退路径：来源标记 `sha256-sidecar`，Windows 最新 0.5.8（158,180,342 字节）、Linux 最新 0.5.0（252,338,348 字节），摘要与大小均与发布资产一致；耗时 7.2 秒。
- 前端 `tsc --noEmit` 与 `vite build` 通过。
